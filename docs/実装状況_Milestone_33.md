# Milestone 33 — 罠の発動操作と反応会話、第六章の寝返り・保存再開

2026-10-12。版は `10.0.0-dev.33`。固定V9.7.75と異なっていた罠の発動タイミングと反応台詞を修正した。人物値・編成・地形・ダメージ・乱数規則は変更していない。保存形式6、内容revision `v10-v9-chapter-catalog-9` を維持。

## 修正した動作

- V9の `moveSelected` は移動先を選んだ時点で経路の最初の罠へ移動し、発動・停止する。V10は攻撃や待機の確定まで罠を発動せず、罠を踏む移動を取り消せていた。まず画面クリックの回帰テストで、修正前の `MOVE_PREVIEW` と本来の `LOCKED` の違いを再現した。
- 脱出専用だったControllerの入口を `canExecuteImmediateMove` / `executeImmediateMove` に整理。罠または脱出勝利が成立する移動を、目的地選択のクリックから通常の移動処理へ渡す。途中停止・敗北優先・イベント・行動終了・中断保存の処理順は共通化したまま。
- 隠し罠の照会はルール層が経路順に行い、罠の位置を画面へ渡さない。照会で部隊・罠・乱数・ログ・保存を変更しない。実行時にも経路と罠を再検査する。通常の移動と罠を把握する人物の移動は引き続き取消可能。
- 実ブラウザーのV9比較で、罠発動後の人物の台詞も抜けていると判明。`trap-dialogue-factory.js` が確定済み結果からSpeech/Dialogueを構築し、Controllerが効果演出後に既存の会話画面へ渡す。正常生存・敗走・妖術罠・妖術無効化・公孫勝の専用台詞を固定V9から復元。
- 反応会話中は操作・保存をロックし、「進む」の後で操作と中断保存へ戻る。妖術罠の初回警告は既存のStageEventが引き続き担当し、反応会話に続く。承認済みの撹乱と幻術の独立保持は維持。

## 第六章の実データによる進行検証

`tests/v9-manor-progression.test.js` で、元の80部隊・人物能力とseed 1を使用。敵AIを止めず、部隊位置・兵力・ターン・イベント完了状態の強制変更なしで、公開コマンドだけを実行した。

1. 第1ターンに王英を `(3,18)` から `(3,14)` へ移動。罠で127→107、撹乱1、北向きで行動終了。乱数の追加消費なし。
2. 残りの味方はその場で現在の向きを保って待機し、敵ターンへ進む。実際に戦闘・敗走が発生する。
3. 第4味方ターンに孫立ら8人が敵から味方へ移り、北向きで行動可能になる。残る敵52隊には撹乱1。罠は1個だけ消費済み。
4. 加入した鄒淵を `(2,7)` から未発動の罠がある `(2,10)` へ通常移動・待機。罠把握によってダメージと状態付与がなく、罠も残る。

罠発動直後（第1ターン）・寝返り前（第3ターン）・寝返り後（第4ターン）の3地点を通常のSaveServiceで保存し、slot guardを通して読み込んだ。再開直後と経路継続後の部隊・位置・状態・使用回数・罠・乱数・イベント・戦況履歴が連続実行と完全一致。導入・作戦条件・寝返り会話の重複再生なし。これは寝返りまでの進行検証であり、勝利経路ではない。
