# Milestone 41 — 表示通知の契約と責務の整理

2026-10-24。版は `10.0.0-dev.41`。ユーザーが再確認した方針「V9の操作を踏襲し、内部構造を整え、その操作を改善する」に沿い、構造評価で挙げた問題を実装で修正した。

## 実装

- `core/presentation-payload.js`で10種類の表示通知の契約を検査。部隊ID、座標、行動種別、兵力、状態異常、ターン、勝敗などの必須項目と値の型を確認する。作成時、受信時、ステージ定義の正規化時に共通の検査を適用。既存のDIALOGUE・NOTICEの検査も維持。
- STATUSはターン開始・罠・行動結果を区別。WAITとILLUSION_WAITは対象なし、通常の攻撃・計略は対象ありという契約を明示。無効な通知は`PRESENTATION_PAYLOAD_INVALID`と種別・フィールド名で検出する。
- `BattlePresentationFactory`へ通知の組み立てを移動。確定済み状態から不変のsnapshotを作り、攻撃結果はDAMAGE→STATUS、罠結果はTRAP→DAMAGE→STATUSの順序を保持する。乱数消費・状態変更・ログ記録・表示待機は行わない。
- `BattleController`は更新と送信の順序を引き続き担当。1,338行から1,215行へ整理。敗走者を盤面から除いた後も、演出には確定結果が持つ位置を渡す。
- `domain/unit-capabilities.js`に撹乱能力の判定を集約。表示・戦闘処理は能力上限、AIは能力上限と残り回数の小さい方を使用する。レベル3の能力があって残り1回なら表示はLv3、AIが選べる上限はLv1という従来の区別を維持。
- 音声・演出の単体テストで省略されていた通知の項目を、実際の契約に合わせて補完。期待する音声・演出・待機時間は維持。
